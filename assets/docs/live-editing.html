Live Editing

These docs are plain HTML files. No markdown, no static site generator, no build step. The source of truth is the HTML itself. But editing content usually means jumping between the browser and a text editor, finding the right line, making the change, saving, switching back, refreshing. For small text fixes that loop is annoying.

I wanted something simpler: click any text on the page, edit it inline, and have it save back to the file automatically. Most solutions I found were either full CMS platforms, required changing the whole stack, or were built for markdown sources. Nothing just worked on raw HTML files with zero setup.

So this is two files: edit.js (the toolbar) and serve.py (the save server). Drop a script tag into any page, start the server, and every doc becomes editable.

IHow it works

edit.js is a self-contained script that injects a thin dark toolbar at the bottom of the page. On load, it is faded out and read-only. Hover to reveal, click edit to make all text elements (paragraphs, list items, table cells, blockquotes, captions) editable via the HTML5 contenteditable attribute. A dashed blue outline shows what is editable.

Click save and the script clones the DOM, strips all editing artifacts (contenteditable attributes, outline styles, the toolbar itself), and POSTs the clean HTML back to the server. The file on disk is overwritten. Git sees the change. On reload, the toolbar re-injects from the script tag. Links remain clickable in edit mode.

serve.py is a 30-line Python HTTP server. It serves static files normally (GET) and handles saves (POST to any .html path). It writes the request body to the corresponding file. That is all it does.

IISetup

Add the script tag before </body> in any HTML file. Adjust the relative path to wherever edit.js lives.

html 
    <!-- at the bottom of your page -->
    <script src="../edit.js"></script>
  </body>
</html>

Start the server from the docs root:

shell 
python3 serve.py

Open any page at http://localhost:8080/. The toolbar appears on every page that has the script tag.

IIIFiles

  • edit.js -- toolbar + save logic. Injects itself into the DOM at runtime. On save, clones the document, removes itself from the clone, serializes clean HTML, and POSTs it. Preserves the <script> tag in the saved output so the toolbar survives reloads. Guard prevents double initialization.
  • serve.py -- Python http.server subclass. Adds a do_POST handler that writes the body to the requested path. Only allows .html files. Serves from its own directory.

IVWhat it edits

The selector is h1-h6, p, li, td, th, blockquote, figcaption, pre code. Headings, paragraphs, list items, table cells, and code blocks are all editable. Structural containers (divs, nav, the page layout itself) are not.

VLimitations

  • Dev-only. No auth, no conflict resolution, no undo beyond browser undo (Cmd+Z works while editing).
  • Cannot add or delete elements. Only edit existing content.
  • The browser may normalize HTML on save (collapse whitespace, reorder attributes). The content is preserved, but formatting may shift slightly.
  • Requires serve.py running. Opening the HTML file directly (file://) gives you the toolbar but save will fail.
