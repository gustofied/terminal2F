t2f eval

After prime eval run finishes, results sit in a directory as two files. The eval viewer starts a local server that reads them and renders an HTML page. Refreshing the browser re-reads the files, so you always see the latest data without rerunning the command.

shell 
# one run
t2f eval view outputs/evals/email-to-cc-bcc--openai--gpt-4.1/e50c41ac

# compare two runs side by side
t2f eval view <dir1> <dir2>

# no args: scans outputs/evals/ for everything
t2f eval view

What it reads

Each run directory has two files. metadata.json carries the config and aggregate numbers: which model, average reward, per-metric averages, how many examples, total time. results.jsonl has one line per rollout: the full prompt, the completion, the reward, individual metrics, and an info dict that can include ground truths.

structure 
outputs/evals/{env}--{model}/{run_id}/
  metadata.json
  results.jsonl

What it renders

At the top, a summary table shows every loaded run in one row: model name, average reward, per-metric columns, example count, error rate, wall time. Below that, a controls bar lets you sort by example ID or reward, filter to a reward range, and expand or collapse everything at once.

The main body groups rollouts by example. Each example group is collapsible and shows its average reward. Inside, each rollout card has a header line with reward and metric badges, the stop condition, and an expandable conversation view. The conversation renders messages by role. When ground truths are available, assistant turns appear side-by-side with the expected answer.

Rewards are color-coded:

ScoreColor
≥ 0.8green
≥ 0.5yellow
< 0.5red
