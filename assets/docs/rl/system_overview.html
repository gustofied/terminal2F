System Overview

VERIFIERS · TRAINER · vLLM — TOPOLOGY & DATA FLOW

IArchitecture

Three processes, two communication channels. The orchestrator lives inside the trainer process and bridges the environment to the training loop.

Fig. 1 — Component topology. Dashed boundary indicates co-located processes. Filled arrows show primary data flow; the red path marks the rollout initiation.

Channel Direction Purpose Protocol
A Verifiers → vLLM Generate completions during rollouts OpenAI HTTP API
B Trainer → vLLM Push updated weights between steps NCCL GPU-to-GPU

IIMulti-Turn Rollout

Inside env.generate(). Verifiers drives the conversation loop. vLLM generates when asked. The trainer never sees this — it only receives the packaged result.

Fig. 2 — Three-turn rollout sequence (email-to-cc-bcc). Scoring happens once at the end; the rubric evaluates all turns together.

IIITraining Step

One full cycle. Steps 1–3 belong to the orchestrator, 4–6 to the trainer, 7 is the handoff.

Fig. 3 — Single training step. Red edge = orchestrator/sync phase. Black edge = trainer compute. Generation and sync never overlap.

IVWeight Sync Timing

Generation and weight sync are mutually exclusive. You cannot sync while vLLM is generating — that would corrupt in-flight inference. You cannot generate during sync — you’d get mixed weights. The trainer enforces: finish generating → sync → start generating.

Fig. 4 — Timeline. The sync window is narrow; most wall-clock time is spent in generation.

VTrainer-Agnostic

Verifiers has no trainer imports. It needs one thing: an OpenAI-compatible endpoint for generation. Any trainer can plug in — it just needs to build an orchestrator that:

  • Calls env.generate() with the vLLM client
  • Parses the trajectory structure — token IDs, logprobs, turn boundaries
  • Builds loss masks — model output = 1, prompt/env response = 0
  • Coordinates weight sync timing around generation

Every trainer that supports verifiers (prime-rl, t2f-trainer, Tinker, SkyRL, rLLM) built this adapter independently. The env and reward functions are portable. The orchestrator glue is not.
