ILogit, Softmax, and Logprobs

I Logit, Softmax, and Logprobs

Instead of zig-zagging I simplify. An LLM neural network has one job: produce a value for each token in its vocabulary. These values are called logits. Apply softmax and take the log, and you get logprobs, the key values trainers use to do reinforcement learning on language models. It's the ingredient, so let's look at what logprobs are, where we find them in the formulas, and some intricacies.

The key to understand is that LLMs do a full pass through the network for each token. On every pass, it assigns a value to each token in its vocabulary, highest to the one it deems most likely. Then the decoder, which is another stage, picks one, feeds it back in, and does another full pass. This is what you call autoregressive. So with 10 tokens said by the LLM, you get 10 vectors of logits. But what do these raw numbers tell you? Not much on their own. A logit of 12.4 versus 11.9, is that a big gap? You can't say. That's where softmax comes in. This network, the thing that produces these logit values, is exactly what reinforcement learning adjusts. RL nudges the weights so the network produces different logits next time, favoring tokens that led to higher reward.

Mathematically: the logit vector z passes through softmax to get probabilities, and taking the log gives you logprobs. These logprobs, always between minus infinity and 0, are what appear in every RL training formula. They measure how confident the model was in each token it produced, and that confidence signal is exactly what the trainer uses to adjust the weights.

When an LLM is writing to you, its output is on a per-token level, one token at a time. A token is that a word? Is that the grammar? Is that the sentence? I'm unsure. The model's grammar of the language says what tokens you can have, so not characters. An LLM or any computer doesn't understand what the character is, it's a token either way. Hey, there might be talking. Hey, there. Now, they. Why they? What's the probability of "they"? Well, that's up to the model, how it was trained. It is a probability it gives, which stems from its logit, which is the final number of the final layer in the neural network, which is assigned to each of them, and the one with the highest often is the one picked. By the way, when you give a prompt to a model, the prompt tokens are all processed in parallel in one pass, because the prompt is already fully known so there is nothing to predict yet. It is only during generation that the model goes one token at a time, since each new token depends on the one before it.

So what actually happens when a model produces a single token? Step by step:

  1. The network runs a forward pass on the input sequence. The final linear layer outputs a vector of logits, one number per entry in the vocabulary.
  2. An activation function (softmax) turns those logits into probabilities that sum to 1.
  3. A token is selected from that distribution (argmax, sampling, top-k, whatever the decoding strategy is). This gives you a token ID, just an integer.
  4. The tokenizer maps that ID back to actual text. That text is the output you see.

The logits are the raw output of the network. The token is the raw output of the system. The network never sees or produces text, it only produces numbers. Everything from step 2 onward is decoding logic that sits outside the neural network itself.

The important thing to know for an LLM is that the logits are the final numerical outputs of the model, which are transformed into probabilities of picking a new token.

Remember from the previous post that tokenizers have a vocabulary that contains all of the tokens the model has been trained on. In OpenAI's GPT2, the vocab contains 50,257 tokens. There is one logit value per token; thus, the final output of an LLM is a vector of 50,257 numbers that is associated with each input token. So if your text has 5 tokens, then the final output of the model will be a matrix of size 5x50257.

Temperature is worth noting here because it operates on the logits, before softmax, not after. You divide each logit by T, then apply softmax. A high T squashes the logits closer together so softmax produces a flatter, more uniform distribution. A low T stretches the gaps so softmax becomes spikier, concentrating probability on the top token. It has to happen before softmax because if you scaled after, the probabilities would no longer sum to 1.

Softmax is a way to transform any set of numbers into a probability distribution. What's a probability distribution? A probability is the chance of something happening or being observed, like "30% chance of rain" or ".00000001% chance of winning the lottery." A probability distribution is a set of probabilities that sum to 100% (or to 1 if not scaled up by 100). For example, "30% chance of rain" is not a probability distribution, but if we'd add to the set "70% chance of no-rain" then we'd have a probability distribution.

The vocabulary is a two-way lookup table. In one direction, encode: you give it text, it gives you token IDs. "they" becomes 4821. Those IDs are the numbers that get fed into the network. In the other direction, decode: the model outputs scores over all IDs, one gets picked, and the tokenizer maps that ID back to text. 4821 becomes "they" again. The model only ever touches the numbers. Text exists on both sides of the model but never inside it.

Logprobs are the natural logarithm of the softmax output. Softmax gives you a probability between 0 and 1, and taking ln of that gives you a number between minus infinity and 0. A probability close to 1 becomes a logprob close to 0. A tiny probability becomes a hugely negative logprob. This is useful because the log stretches out the differences at the low end. Going from probability 0.001 to 0.002 is nearly invisible on a 0-to-1 scale, but in log space it is the difference between -6.9 and -6.2, a meaningful jump the gradient can act on. At the top end the opposite happens: going from 0.95 to 0.96 barely moves the logprob. So the model gets strong signal when it improves on things it is bad at, and does not waste effort squeezing tiny gains where it is already confident. This is why training works in log space.

Temperature and sampling strategy are two separate things. Temperature reshapes the distribution, it does not decide what gets picked. The sampling strategy decides how to pick from the distribution. Greedy (argmax) always picks the highest probability token. Top-k limits the selection to the k most probable tokens, then samples among those. Top-p (nucleus sampling) keeps the smallest set of tokens whose cumulative probability exceeds p, then samples from that set. Multinomial sampling picks randomly according to the full probability weights. You can combine them: temperature first to control the shape, then a sampling strategy to pick from the result.

Softmax
$$p_i = \frac{e^{z_i}}{\sum_j e^{z_j}}$$
Logprob
$$\log p_i = z_i - \log \sum_j e^{z_j}$$
The term in RL formulas
$$\log \pi_\theta(a_t \mid s_t)$$

The logprob of action $a_t$ given state $s_t$ under policy $\pi_\theta$. This is the term that appears in Policy Gradient, REINFORCE, PPO, GRPO, and every other RL training loss.
